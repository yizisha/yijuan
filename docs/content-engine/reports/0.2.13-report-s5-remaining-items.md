## 1. 滑动模式插图（原缺口：只有分页模式有图）

**做法**：把「段落 → 文本/图片片段」的切分抽成**一个纯函数**
`splitParagraphForImages(text, baseOffset, bodyShift, imagesByOffset)`，分页与滚动**共用**。

- 为什么不各写一份：偏移怎么算只允许有一个答案。0.2.9→0.2.11 的三次缺陷全部出在
  "两处实现/两处调用对同一件事理解不一致"（切分、缓存键、参数漏传），重复实现必然再次分叉。
- **偏移连续性**：图片占它自己那个 U+FFFC，紧随的文本从 **+1** 继续；滚动模式的
  `paragraphStart`、`blockId`、`DisplayMapping` 全部按片段重新给定，
  因此滚动位置保存（Gate G4 的那条链路）与批注/书签坐标不受影响。
- **bodyShift**：`ChapterBody.stripLeadingTitleEcho` 会去掉与标题重复的开头行，
  而图片偏移是 **content 坐标** —— 必须补回位移，否则图会落到别的段落上（跨文档/带回显的书才看得出来）。
- 没有插图的段落只会得到**单个 Text 片段**，排版与从前逐字节一致（不引入回归）。

## 2. 图片放大预览（4.6 第 10 条）

新增 `ReaderImagePreviewDialog`，由 `ReaderScreen` 承载（两个渲染器共用）：

- **手势隔离**：用独立 `Dialog` 呈现，缩放/拖动/双击/点击都在预览层消费，

  关闭即回到原处（4.6 第 10 条末句）；
- 底部显示图注/alt。

## 3. 解码失败 error UI 与 alt 文案（4.6 第 9 条）

`ReaderImage` 重写为**三种可区分结果**，都**不静默留白**（INV10）：

1. 路径为空 / 文件不存在 → 「图片缺失」占位 + alt；
2. 文件在但**解码失败** → 「图片无法显示」占位 + alt
   （用 `SubcomposeAsyncImage` 的 error 槽位拿到这个状态；旧实现是 `AsyncImage`，**没有 error 槽位**，
   解码失败就是一片空白）；
3. 正常 → `ContentScale.Fit`，可点击预览。

## 4. 解码字节预算与视口采样（11.2）

`FlowReaderApplication` 实现 `ImageLoaderFactory`，应用级 Coil 加载器：

- **位图内存预算 = `min(64MiB, memoryClass / 8)`**（11.2 原文），不再用 Coil 默认的
  "可用内存百分比"——后者随系统压力漂移，无法作为验收口径；下限 8MiB（heap 很小时别把一屏都放不下）；
- **解码并发上限 2**（11.2 第 4 条）：独立的 2 线程池作为 Coil dispatcher；
- **视口采样**：解码尺寸由 Composable 的布局约束决定（`SubcomposeAsyncImage` 按目标尺寸请求），
  且分页模式用的是**分页器已测得的像素高度**，因此**不会**把整本大图按原尺寸解进内存；
- 启动日志会打印实际预算与并发（`adb logcat | grep "Coil image loader"`），便于真机核对。

> **需要知悉的取舍**：`dispatcher` 是加载器级配置，所以这条 2 并发的限制对**全应用**的图片解码生效
> （书架封面也包含在内）。这是按 11.2 的字面要求做的；若你希望书架封面不受限，我可以改成
> 只在阅读器内使用一个独立 `ImageLoader`（`AsyncImage(imageLoader = ...)`），代价是多维护一个加载器。
> **请你确认**要哪种。

## 5. 列表 / 表格 / 注音：为什么不在本批，以及怎么做

**根因（已核实）**：阅读器渲染的是**规范正文文本**，而这三类语义**不在文本里**：

| 语义 | 规范正文里有什么 | 结论 |
|---|---|---|
| 列表 | **只有 LF**，没有项目符号/编号（`emitListItem` 不写标记） | 无法从文本还原"第几项、是否有序、嵌套层级" |
| 表格 | 单元格之间是 **TAB**（`emitTab`），无表头/跨行跨列信息 | 只能看出"有分栏"，看不出表格结构 |
| 注音 ruby | **只保留基字**，`rt/rp` 注音按 3.2 第 6 条**不进主文本** | 文本里根本没有注音内容 |

**因此必须把结构语义也写进内容包**（与 0.2.9 给图片做的同一套路数，schema → v3），
再由渲染层按偏移注入。这需要：

1. `PublicationStore.buildDocumentJson` 增加 `lists` / `tables` / `ruby` 数组
   （列表：ordered/start/level/每项 value 与范围；表格：行/列/表头/rowSpan/colSpan；ruby：基字范围 + 注音串）；
2. 解析器侧把这些字段从已有的 `ListBlock` / `TableBlock` / `RubyBlock` 带出来（数据都在，只是没持久化）；
3. `ChapterImageResolver` 扩展成"章节标注解析"（或并列一个解析器），仍**只读当前 section 的文档**；
4. 渲染层把标注注入排版（列表编号由**结构位置**推导，天然满足 G5 的"长列表续页编号不重置"；
   表格按列对齐；ruby 以上下小字呈现）；
5. 测试：编号不重置、跨页连续、表格列数一致、ruby 不进主文本偏移。

⚠️ schema 升 v3 后**又需要重新导入一次**才有这些标注（与 v2 同理：旧包没有该字段）。
