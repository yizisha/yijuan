# FlowReader — 0.2.9 报告（S5 第一步：结构插图真正渲染出来）

日期：2026-09-11。触发：用户指示「开始」（开始 S5），此前已确认本批必须**不把卡顿带回来**。

版本 **0.2.9**（versionCode **5682**）。

---

## 1. 本批做了什么（一句话）

**EPUB 的插图第一次真正显示在正文里**（分页模式），并且这条链路是**成本与书规模无关**的：
只读当前 section 涉及的 1–2 个文档，不读整本书。

同时纠正一个更上游的事实：**插图不显示并不只是"UI 少写了一段渲染"** ——
解析器把段落**内部**的图片对象丢掉了，持久层也没有记录「哪个偏移是哪张图」。
所以这是一条四层的断链，本批四层都补上了。

---

## 2. 断链的四层（每一层都有证据）

| 层 | 问题 | 证据 |
|---|---|---|
| 1. 解析器 | `<p>文字<img/>文字</p>` 这种行内图，图片对象**没有进 blocks**：`emitInline` 只把它塞进 `lastInlineImage`，仅当"整块就是一张图"时才提升为 `ImageBlock`（`EpubDocumentParser.kt:499-517`） | 本批新增测试 `PublicationImageIndexTest.inlineImageIsPersistedWithItsOffsetAndResource` **修复前实测得到 0 条图片** |
| 2. 持久层 | 文档 JSON 只写 `blocks`（blockId/domPath/role/start/end/type）与 anchors/weightIndex，**没有图片的资源与偏移** | `PublicationStore.buildDocumentJson`（v1）；设备上 `documents/*.json` 里没有 `images` |
| 3. 数据层缺映射 | `manifest.json` 的 `resources` 是**按 containerPath 排序**的去重清单，跨文档顺序与偏移全部丢失；`resourceIndex()` 零调用 | 设备实测：`0a9c0038`（魔法禁书目录 01）包内 **18 张 JPEG**，但没有任何偏移信息 |
| 4. 渲染层 | `PagedReader` / `ReaderContent` 只认旧的 `[IMG:路径]` 标记，而新导入路径已不再产生它；`U+FFFC` 在 UI 层零渲染 | 全工程 grep：`U+FFFC` 只出现在解析器/清单/注释里 |

## 3. 修复

### 3.1 模型：文档自己记住"每个图片对象"

- `StructuredDocument` 新增 `images: List<ImageBlock>`（附在末尾并有默认值，不影响既有构造）。
- `ImageBlock` 新增 `alt`（原本 alt 只进了诊断，占位时无从显示）。
- `EpubDocumentParser` 的 `WalkContext` 新增 `images`，在**唯一创建图片对象的地方**
  （`emitImageInline`）记录一次 —— 行内图、块级图、figure 里的图自动全覆盖，不可能漏。
- 于是不再需要"从 blocks 里找图"这种有洞的做法；blocks 遍历仅作为外部构造文档时的兜底。

### 3.2 持久层：文档 JSON 写入 `images`

`PublicationStore.buildDocumentJson` 输出：

    "images": [ { "blockId", "domPath", "offsetUtf16", "containerPath", "raw", "alt", "role" } ]

- `offsetUtf16` = 该图占用的 `U+FFFC` 偏移（`ImageBlock.objectOffsetUtf16`）。
- `containerPath` 为空 = 外部/被拒引用 → 读回时解析不出路径 → 渲染层显示占位（INV10）。
- 同时新增 `readPackageIndex()`（一次读 manifest.json：section 范围 + 文档 JSON 路径 + 资源路径）
  与 `readDocumentImages()`（读一个文档的 `images`）。两者**都不抛异常**，旧格式/坏文件返回空。

### 3.3 格式版本：v1 → v2，并让"重新导入"成为升级路径

`StructuredDocument.CURRENT_SCHEMA_VERSION` **1 → 2**。
`BookParser` 已经把该值算进 revision，因此：

- 重新导入同一本书 → **新的 revision 目录**（旧目录按 5.3 保留、不覆盖），新包带 `images`；
- 已存在的书不受影响：它们的 `activeRevision` 仍是旧值，定位 Tier-1 照旧命中，不会被强制重解析。

### 3.4 坐标换算：纯粹、可测、跨文档正确

新增 `ChapterImageIndex`（纯函数）：把「section 的多个 range」按 `projectChapters` 的拼接顺序
换算成**章内偏移**。跨文档的 section（一个 section 含两个 XHTML）必须按前面 range 的累计长度平移，
否则图片会落到别的段落上；落在区间外的图片不并入本章。

### 3.5 解析器：`ChapterImageResolver`

- 按 revision 缓存包索引、按文档缓存图片表（LRU：3 个包 / 64 个文档）。
- **只读当前 section 涉及的文档**（通常 1–2 个）。
- 全部在 IO 线程；失败/旧书/无包 → 空列表。

### 3.6 渲染：测量与渲染同源（复用既有通道）

- `buildChapterBlocks(title, content, indentEnabled, images)`：把 `U+FFFC` 换成**独立的图片块**，
  文本段之间的**偏移连续**（图片占它自己的偏移，后续文本从 +1 继续），
  否则批注/书签/进度会整体错位。
- 图片块复用既有的 `[IMG:路径]` 通道：`measureBlock` 用 `BitmapFactory` 只读尺寸算出
  **与 Composable 完全相同**的高度（`ContentScale.Fit`，且封顶一页高），
  于是"分页占位"与"实际绘制"用的是同一套几何（4.6 第 7 条的实质要求）。
- **该标记只存在于内存的排版块里**，绝不写回 `chapters.content`
  （`PublicationImportGoldenTest` 是 F10 回归防线）。
- 资源缺失 → 空路径 → `ReaderImage` 显示 120dp 损坏占位（测量同样按 120dp 计入），不会静默丢图。

### 3.7 不破坏「成本与书规模无关」

- 图片在**发布章节状态之前**解析好：分页一次算对，不会"先按无图排版、再重排一次"。
- 分页缓存键新增 `imageKey`（偏移 + 解析结果）：**有图与无图是两份缓存**，不会复用一个少图的旧排版。
- 相邻章预排版也带图片（否则预热出的页与真实页不一致）。
- `ReaderChapterLoadCostTest` 保持绿色：换章仍然**只读 1 章正文**，与章数无关。

## 6. 怎么看效果（需要你操作一次）

**已导入的旧书必须重新导入一次**才会带图片：你现有的两本 EPUB 是用 v1 格式落盘的
（文档 JSON 里没有 `images`）。请对含插图的那本（**魔法禁书目录 01**，包内 18 张 JPEG）

1. 在书架长按/详情页删除该书，再重新导入同一个 EPUB 文件；

> 删除会一并删掉该书的书签/批注，请先确认没有要保留的笔记。
> （"原地升级、不动用户数据"属于计划书 S10/迁移执行器的工作，本批没做。）

2. 重新导入后进入**分页模式**，翻到有插图的章节（封面、章首彩页）。

应当看到：插图按原书位置出现，图上方/下方文字不被吞、图不被截断；
若某张图缺失，应显示损坏占位图标。

**滑动模式（无翻页/滑动）的插图本批未接**，那里仍只有占位字符 —— 这是已知缺口。

### 7.1 未跑的门禁

- `:app:connectedDebugAndroidTest`（真机 instrumentation）**未重跑**，沿用 0.2.4 的 7/7 基线。
- 本批改动了 `StructuredDocument` 与 `EpubDocumentParser`（图片对象采集）与 `PublicationStore`
  （文档 JSON 增 `images`），**导入链路**是新增字段的路径；因此
  `PublicationImportOnDeviceTest` / `TocTreeOnDeviceTest` 建议在本阶段收尾时重跑一次。
- **真机"看得见"未验收**：需要先重新导入一本含插图的 EPUB（见第 6 节）。

### 7.2 已知风险（不掩盖）

1. **大图峰值内存未测量**：仍用 Coil `AsyncImage` 默认尺寸解码，没有 §11.2 要求的
   字节预算与视口采样。你这本 EPUB 单图最大约 145 KB（18 张），风险低；但
   "100 万字 + 200 张图"的验收场景**未测**。
2. **旧书必须重新导入**才能有图；且重新导入会新建 revision（旧 revision 目录会保留，
   不会丢数据），长期会积累磁盘占用 —— 清理规则属于 S10。
3. **滑动模式仍是占位字符**（本批只接了分页模式）。
4. 同一本书**旧 revision 与用户书签/批注**：重新导入不改书签/批注行，但它们保存的
   `revision` 是旧值，恢复时会走 Tier-2/3（上下文匹配/百分比），位置可能略有偏移；
   这是既有设计（revision 变化即需重解析定位），不是本批引入。
