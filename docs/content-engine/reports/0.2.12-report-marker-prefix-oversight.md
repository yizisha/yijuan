# FlowReader — 0.2.12 报告（修复：残缺图片标记仍被当正文渲染 —— 0.2.10 的修复范围不够）

日期：2026-09-11。触发：用户装 0.2.10/0.2.11 后再次截图，插图旁边**仍有路径文字**，
且形态变了：

- 一页里出现 `:/data/user/0/com.flowreader.app/files/books/5b8ba59a-…/resources/9566c0…090]`
  （**开头没有 `[IMG`**），
- 另一页出现**单独的 `[IMG`**。

即：图片标记被**从中间切开并分到两页**。版本 **0.2.12**（versionCode **5685**）。

---

## 1. 根因：0.2.10 只挡住了"较长"的残缺前缀

0.2.10 的规则是：

    text.startsWith(IMAGE_MARKER_PREFIX) -> UNSPLITTABLE_IMAGE_HEIGHT_PX   // IMAGE_MARKER_PREFIX = "[IMG:"

而 `ChapterPaginator.findSplit` 是**二分搜索**，它会试探
`text.substring(0, 1)`、`(0, 2)`、`(0, 4)`… 这些**比 `[IMG:` 更短**的片段：

- `"[IMG"` **不以 `"[IMG:"` 开头** → 落到 `else` → 按普通段落测量（高度很小）→ 分页器认为
  "这一小段放得下" → `best = 4` → 切出 `[IMG`，其余部分留到下一页。

⇒ 真机现象正是截图所示：**`[IMG` 与 `:/data/…` 被分成两段绘制**。

> 为什么 0.2.10 没发现：我当时随手写的"被切开的例子"是 `[IMG:/data/user/0/…`
> —— 它**带冒号**，正好落在旧条件的覆盖范围内，所以测试是绿的。

---

## 2. 修复

新增 `isImageMarkerFragment(text)`：判断文本是否是图片标记的**任何残缺前缀**，
包括短于 `[IMG:` 的 `[`、`[I`、`[IM`、`[IMG`：

    internal fun isImageMarkerFragment(text: String): Boolean {
        if (text.isEmpty()) return false
        return if (text.length < IMAGE_MARKER_PREFIX.length) {
            IMAGE_MARKER_PREFIX.startsWith(text)   // 短前缀：是标记前缀的前缀
        } else {
            text.startsWith(IMAGE_MARKER_PREFIX)
        }
    }

`measureImageAwareText` 用它在**完整标记**判定之后兜住所有残片，一律报"放不下"，
分页器因此永远拿不到可以切分的标记 → 整张图换页。

---

## 3. 测试：先证明它会失败，再修

这是本批最重要的一点。新增/加强两项，并**故意把生产代码退回 0.2.10 的旧规则验证**：

| 测试 | 在旧规则下的结果 |
|---|---|
| `everyTruncatedMarkerPrefixIsReportedAsUnfittable`（遍历 `[`…`[IMG:/abs/a.jpg` 全部前缀） | **FAILED** |
| `anImageThatDoesNotFitTheRemainingPageMovesWholeToTheNextPage` | **FAILED** |

    PagedReaderImageBlocksTest > everyTruncatedMarkerPrefixIsReportedAsUnfittable FAILED
    PagedReaderImageBlocksTest > anImageThatDoesNotFitTheRemainingPageMovesWholeToTheNextPage FAILED
    9 tests completed, 2 failed

**第二项之所以原来漏判**：0.2.10 的集成测试用的是 `pageHeightPx = 120`，
标题+正文正好占满，`available = remaining - gap = 0`，
于是 `if (available > 0)` 不成立、`findSplit` **根本没被调用**。
现在改成 `pageHeightPx = 200`（剩余 80 < 图片高 100），**确保走到 `findSplit` 那条分支**，
并额外断言第一页内容恰为 `[标题, 正文]`、第二页恰为整张图。

> 教训（已写入 HANDOFF §6）：**测试必须真的走到出问题的那条分支**；
> 只断言"结果正确"而不覆盖分支，等于没测。

## 4. 附带：安装后必须重启应用进程

上一轮 `install -r` 之后我没有强制重启应用；用户 23:45 的截图有可能仍在旧进程上
（Android 有时不会立刻换掉已加载的代码）。本批安装流程改为
**安装 → `am force-stop` → `am start`**，确保跑的是新版本。
