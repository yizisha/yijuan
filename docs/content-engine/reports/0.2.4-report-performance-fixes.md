## 1. 三处逐章 N+1 查询（卡顿主因）

### 1.1 打开书时全量重索引（影响最大）

ReaderViewModel.indexBookForSearch 在**每次打开书**时删掉该书索引并**逐章**重建。
一本 491 章的书 → 491 次查询 + 491 次 FTS 写入，且是在**持有全局索引锁**的情况下，
因此同时会阻塞搜索。这是「打开书/导入后卡很久」最合理的解释。

**顺带修掉一个正确性缺陷**：这里用的是**循环下标**而不是 chapter.index。
章节号跳号时（本项目 TXT 导入确实会出现）会**读到错误章节的正文并索引到错误位置**。

### 1.2 全文索引重建

SearchRepositoryImpl.rebuildIndexLocked 同样逐章读取，且由「书集合变化」触发
（即**导入新书后第一次搜索**会重建全库索引）。

### 1.3 搜索回正文验证

S7 为「用命中文本投影验证」新增的投影，对每条结果单独查正文；一次搜索最多 100 条 → 100 次查询。

### 修复方式

新增**批量取正文**并分块使用：

- ChapterDao.getChapterContents：WHERE bookId = ? AND index IN (?)
- 先吃内存缓存，剩余**一次**查询补齐；
- 按 FullTextSearch.INDEX_CHUNK_SIZE = 32 分块，避免超大书整本正文同时驻留内存。

## 2. 书架网格书封高低不齐

LibraryScreen 网格项标题用 maxLines = 2：**单行标题的卡片比双行标题矮一行**，
同一行里书封看起来高矮不一。

修复：标题改为 minLines = 2, maxLines = 2，每个书格恒定两行高度。

## 2.5 底部 dock 栏（用户澄清后的补充）

现象：底部 dock 栏里「书架」二字离底边很远、图标又贴着栏顶，间距很怪。

根因（Navigation.kt）：

```kotlin
NavigationBar(modifier = Modifier.height(64.dp), ...)   // ← 硬编码高度
```

Material3 的 NavigationBar 按 **80dp** 设计，并在内部为**自己**加上底部导航栏
（手势条）inset 的内边距。把它压到 64dp 后，扣掉 inset 只剩十几到几十 dp，
图标+文字这组内容被挤压：图标顶到栏顶、文字被压到很低。

修复：**去掉硬编码高度**，恢复系统默认，让 Material3 自己处理 inset 与间距。
（ShellWindowInsetsTest 使用的是它自己的 NavigationBar，不受影响，测试仍全绿。）

## 2.6 导入问题：两个已确证的缺陷（用户澄清「当时在书架(全部)」后定位）

用户确认导入时停在**书架(全部)**，因此「导到别的分组所以看不见」的假设**不成立**。
继续排查后确证两个缺陷：

### 缺陷 A：每次导入把整本书**多拷一遍**

BookImporter.importSingle 里 copyFileToInternal 被调用**两次**（先拷一次查重、解析后再拷一次），
而 BookParser.copyFileToInternal 是**按文件名覆盖式拷贝、没有存在性检查**，
路径又完全确定（books/<文件名>）。几十 MB 的书就多拷几十 MB —— 导入慢的直接来源。

修复：只拷一次，把路径复用下去（PDF 仍走自己的落盘路径）。

### 缺陷 B：导入期间**没有任何可见反馈**

LibraryScreen 只在**书架为空**时才显示加载态：

    if (uiState.isLoading && uiState.books.isEmpty() && uiState.categories.isEmpty())

书架已有书时（正常情况），大书导入耗时较长而屏幕**毫无变化** ——
这正是「点击导入书籍会没反应」的确切来源。用户以为没反应而离开/切屏，自然也就「书架上没有」。

修复：导入成功后在既有 snackbar 通道上给出「已导入《书名》」，
既回答「有没有反应」，也回答「书去哪儿了」。

**仍未确证**：是否存在**导入失败**（而非慢/无反馈）。若导入真的失败，
uiState.error 会走 snackbar 显示；如果看到的确实是一条错误提示，把提示文字给我，我按错误码继续定位。

## 3. 导入问题的分析（历史记录：曾怀疑筛选，已被用户排除）

现象 1：点「导入书籍」没反应。
现象 2：选完文件后书架上没有这本书。

我查到的线索：

1. **书架列表是 Room Flow 实时订阅的**（`LibraryViewModel.observeBooks()` 用 `combine` 收集），
   导入成功后**应该**自动出现。所以「没有」更可能是**导入失败**或**导到了别处**。
2. **代码里已有一条明确警告**（`LibraryViewModel.importBook` 的注释）：

   > Imports land in the group that is currently selected... the shelf is filtered to that
   > group, so a book that went to `全部` would appear to have vanished.

   也就是说：**如果导入时正处于「最近阅读 / 收藏」这类智能视图，或某个分组筛选下**，
   新书会被放进当前选中的分组（或落到 `全部`），而书架正被筛选成别的集合
   → 看起来就是「导入后书架上没有」。这与你描述的现象高度吻合。
3. 导入失败时**会**弹 snackbar（`uiState.error` → `LaunchedEffect` 显示），
   但如果失败原因是静默的（例如 SAF 只给了不可读的 URI），可能什么都没显示。

**我没有改导入逻辑**：没有确证之前不动它，避免把「看得懂的行为」改成「看不懂的行为」。

需要你确认一件事：**导入失败时，你当时停在书架（全部）还是在某个分组 / 最近阅读 / 收藏？**
